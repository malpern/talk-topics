01 · The shared dependency

Different tools. One native text contract.

A Mac app does not get direct access to a web page’s DOM. It asks Chrome’s macOS accessibility bridge for the field’s value, computes a range in that value, then asks Chrome to select or replace that range.

The accessibility value has 35 UTF-16 units because block boundaries become paragraph separators.

Chrome selects as ifAlphaOwnerBravoTargetCharlieOwner

The internal separator-free text has 33 units. After the first boundary, the same number points at different text.

02 · Why it matters

A one-character drift becomes broken automation.

The failure is not specific to one app. It appears wherever a native client trusts the coordinates of the accessible text Chrome itself returned.

01 / KindaVim

Vim motions target the wrong characters.

A command calculated from accessible text can begin late, cross the wrong boundary, or omit the paragraph separator it meant to act on.

02 / Bear workflows

Text transfer is no longer dependable.

Automation that selects, copies, or replaces Chrome text before moving it into Bear can corrupt the intended slice without an obvious API error.

03 / AI on macOS

Agents need a trustworthy universal bridge.

Without an app-specific API, Accessibility is how an agent reads and edits ordinary text fields. Honest coordinates are foundational capability, not a special-case feature.

03 · Why we studied before submitting

Understanding is part of the deliverable.

We will not ask Chromium owners to validate a tool-generated guess. We reproduced the platform defect, read the production paths, refined the architecture after three independent reviews, and built exact red-to-green tests. The candidate remains local and unsubmitted while Micah completes his own review.

What is observed

  • Official Chrome and Canary select shifted text while Safari follows the exposed value.
  • On the pinned current-main base, all eight Cocoa cases fail before the fix.
  • The candidate passes 10/10 focused tests and a real multi-block browser test 1/1.
  • The old native setter reaches a Blink DCHECK in that browser regression.
  • The full 1,452-test accessibility runner succeeds.

What is proposed—not yet approved

  • One macOS issue for selected range, selected text, and string-for-range.
  • Authoritative generated-newline records carry the exact following tree anchor.
  • A short-lived Cocoa mapper translates one snapshot and fails closed.
  • Two dependent CLs keep shared metadata separate from Cocoa behavior.
  • Owner review decides the shared seam, O(document) cost, and ignored-node policy.
