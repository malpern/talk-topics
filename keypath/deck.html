How Do You Test a Keyboard Remapper?

Build a keyboard that acts, a Jig that witnesses, and an evidence artifact that refuses to bluff.

The trap

A remapper can look correct while emitting the wrong thing.

UI snapshots prove the explanation. Unit tests prove transformations. Neither proves what crossed USB—or whether the last key was released.

On the ESP32 screen

The actor cannot declare itself correct.

The physical screen ends with HID SENT and CHECK JIG FOR RESULT—never “passed.”

The 240×280 touch display exposes run state and timing pressure. Touch and the physical button remain available for abort; the motion governor sheds display work before it competes with HID delivery.

Inside the ESP32

Timing belongs on the device.

Wi-Fi loads and arms a bounded script. After start, the ESP32 schedules each press and release locally, so network jitter cannot alter inter-key timing.

The scheduler yields when it has room, then precision-spins near the next report deadline. USB service, control, sound, and display stay off the HID core.

fixture_runtime.c · cooperative HID scheduler 
wait_us = fixture_time_until_next_action_us(
    &fixture, now_us);

if (!running) {
    vTaskDelay(pdMS_TO_TICKS(5));
} else if (wait_us > 1500u) {
    uint32_t sleep_ms = (wait_us - 1000u) / 1000u;
    if (sleep_ms > 10u) sleep_ms = 10u;
    vTaskDelay(pdMS_TO_TICKS(sleep_ms));
} else {
    esp_rom_delay_us(25u);
}

The independent witness

The Jig fails closed.

FOCUSED is evidence, not decoration. Moving focus invalidates the run. Expected and received text stay side by side; the live keycap stack preserves fast event order; partial evidence stays partial.

Inside the Jig

“Passed” is a conjunction.

CaptureSession.swift · terminal classification 
if focusLost || repeatEvents > 0 ||
   duplicateDownEvents > 0 ||
   unmatchedUpEvents > 0 ||
   mismatchIndex() != nil {
    state = .failed
}

if received == expected,
   pressedKeyCodes.isEmpty,
   activeModifiers == 0 {
    state = .passed
}

The oracle checks exact characters, order, repeats, duplicate downs, unmatched ups, modifiers, release state, timeout, and focus ownership.

That turns a foreground demo into a machine-readable result with a timestamped event ledger and persisted JSON.
