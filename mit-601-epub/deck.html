CHAPTER · 02

The pipeline.

Three tools do the heavy lifting. The hard part is turning a fixed PDF into structured text.

THE TOOLCHAIN

Three tools, in order

  1. Marker — an ML document parser. Detects layout, reading order, tables, figures, and equations. The hard part.
  2. pandoc — builds the reflowable EPUB3, turns LaTeX math into MathML. The assembler.
  3. epubcheck — validates the output. 0 errors = ship it.

Plus a ~150-line Python script in the middle to clean up the raw Markdown. That's the whole stack.

Marker does the genuinely hard ML work. pandoc and epubcheck are off-the-shelf. The glue is a small, book-specific cleanup script.
THE FLOW

CHAPTER · 03

The recipe.

Five steps. Convert your own PDF this afternoon.

STEPS 1–2

Install, then extract

# 1. Install. Marker needs Python 3.12+
brew install pandoc epubcheck
python3.12 -m venv .venv && source .venv/bin/activate
pip install marker-pdf pillow

# 2. Extract PDF → Markdown (+ one image per figure)
#    On Apple Silicon: TORCH_DEVICE=mps
marker_single book.pdf --output_dir out --output_format markdown

Marker isn't fast — a 320-page book took ~90 minutes. It's doing real ML inference on every page.

Python 3.12+ matters — older wheels hit a dyld/SciPy loader bug on current macOS. Marker is slow but that's the cost of good structure extraction.
STEP 3

Clean up the Markdown

The raw output needs light repair. A ~150-line Python script (02_clean.py) handles it:

  • Strip running headers & page numbers
  • Fix heading levels
  • Reattach "Figure N" captions to their images
  • Tidy equations

The patterns are book-specific but small. Most of the work is regex against the page furniture.

This is the only custom code. It's small and tailored to one book's quirks. Don't over-engineer it — match the patterns you actually see.
STEPS 4–5

Build, then validate

# 4. Build a reflowable EPUB3 — math becomes MathML
pandoc clean.md \
  --from=markdown-raw_html+tex_math_dollars+superscript+subscript \
  --to=epub3 --mathml --toc --toc-depth=3 --split-level=1 \
  --css=epub.css --epub-cover-image=cover.png \
  -o book.epub

# 5. Validate, then copy to the reader over USB-C
epubcheck book.epub   # 0 errors / 0 warnings = ship it

--mathml makes equations scale with the font instead of being a fixed image. -raw_html keeps stray OCR tags from breaking the file.

The pandoc flags are the heart of it: epub3 + mathml + split-level for chapter files + disabling raw HTML so OCR junk tags don't corrupt the EPUB.
CHAPTER · 04

What to watch for.

The gotchas that cost me time, so they don't cost you any.

THE GOTCHA

The model misread one symbol
322 times

In the Signals chapter, Marker read the R (delay) operator as \Re — the "real part" symbol ℜ — in 322 equations. 

sed -i '' 's/\\Re/R/g' clean.md   # one line, 322 fixes
Trust the model. Verify the OCR.

The find-replace was safe only because I read the text and confirmed the book never means "real part."

This is the laugh-and-wince moment. ML extraction is great until it confidently makes the same mistake hundreds of times. You have to actually read the output to catch it.
LESSONS

Five things to watch

  • Use Python 3.12+. Older Marker wheels fail to load on current macOS (dyld / SciPy).
  • Verify the OCR. The model can repeat one mistake hundreds of times. Read the output.
  • Equations are MathML. Good readers render it beautifully; weak ones ignore it — fall back to images.
  • Grayscale & shrink images. Screen is gray and ~480px wide. Cap the long edge ~760px.
  • GitHub Pages? Add .nojekyll, or any asset starting with _ silently 404s.
The .nojekyll one bit me directly — Marker names every figure _page_NN_Figure.jpeg, and Jekyll hides underscore-prefixed files. Whole talk's hero images vanished until I added the file.
