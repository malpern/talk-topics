CHAPTER · 01

The problem.

Your agent needs an API key. You have it. How do you hand it over without leaking it?

THE NAIVE WAY

"Just paste the key in chat."

The obvious move is also the leak. The moment a secret becomes text the agent can read, it's everywhere the text goes:

  • The transcript — every message is logged, summarized, and often shipped to a model provider. Your key rides along.
  • The process list — pass it as an argument and ps aux shows it to every user on the box.
  • Shell history — export KEY=… lands in ~/.zsh_history in plaintext, forever.

THREE FAILURE MODES

Every easy path is a leak.

Where it goesWhy it leaks

In a filePlaintext on disk → backups, Spotlight, a stray git add .
In env / argvVisible in ps, inherited by child processes, lands in history

The common thread: the secret became a string the agent handled. To be safe, it never can.

THE REQUIREMENT

The value enters a SecureField — and stops there.

What we actually need is narrow and precise:

  • A human types the secret into a native macOS SecureField — no clipboard, no chat.
  • It flows directly into encryption and never becomes a string the agent can read.
  • The agent can still drive the whole thing — pre-fill the key name, launch, read the outcome.

The agent orchestrates. The human supplies the one thing the agent must never see.

CHAPTER · 02

The stack.

Encrypted secrets, committed to git, decryptable on every machine — without a Keychain or an interactive shell.

FOUNDATIONS

sops + age

  • age — a tiny, modern file-encryption tool. One keypair. The private key lives at ~/.config/sops/age/keys.txt (chmod 600, never committed).
  • sops — encrypts values in a structured file while leaving the keys readable. So a dotenv stays diff-able and reviewable; only the secrets are ciphertext.

The encrypted file is committed to a private git repo. The repo is the source of truth; the age key is the only thing that decrypts it.

CONSUMPTION

Every wrapper self-decrypts.

# inside ~/.local/bin/lin, gmailq, notion, figma… each tool decrypts itself:
KEY=$(sops -d ~/dotfiles/secrets.env | grep '^LINEAR_API_KEY_WORK=' | cut -d= -f2-)
  • No Keychain — it fails in non-interactive shells and can wipe creds.
  • No interactive unlock — the age key is found on disk; sops never prompts.
  • Works anywhere — agent shell, cron, SSH, a launchd job. Same path, every time.

ADDSECRET.SWIFT

The pipeline — value flows as stdin, never argv.

// decrypt → modify in memory → re-encrypt via stdin → write → commit → sync
let dec = run(SOPS, ["-d", SECRETS])              // 1. decrypt to memory
var lines = dec.out.split(separator: "\n").map(String.init)
// …find-or-append  key=value  in `lines`…
let plaintext = lines.joined(separator: "\n") + "\n"

// 2. re-encrypt. THE secret rides stdin — it is never an argument:
let enc = run(SOPS, ["-e", "--input-type", "dotenv",
                     "--output-type", "dotenv",
                     "--age", AGE_PUB, "/dev/stdin"], stdin: plaintext)

try enc.out.write(toFile: SECRETS, atomically: true, encoding: .utf8)  // 3.
run(GIT, ["-C", DOTFILES, "commit", "-m", "secrets: set \(key)"])      // 4.
run(GIT, ["-C", DOTFILES, "push"])                                     // 5. → SSH sync

/dev/stdin is the whole trick: the plaintext never appears in argv, so it never shows up in ps.

CHAPTER · 04

The agent protocol.

How an AI agent asks for a secret it must never see — launch, block, poll, move on.

STEP 1 · LAUNCH & BLOCK

Open the app, pre-filled, and wait.

open -W -n "/Applications/Add Secret.app" --args --key ANTHROPIC_API_KEY
  • --key pre-fills the key name so the human only types the value.
  • -W makes open block until the window closes — the app quits on Done or close, so the call always returns.
  • -n forces a fresh instance. One Bash call, in and out.

The agent is now parked on a single blocking command while a human does the one private part.

THE INVARIANT

What the agent never sees.

The value's entire life is:

SecureField  →  sops stdin  →  ENC[AES256_GCM,…]

  • It never becomes a Swift String the agent's transcript could capture.
  • It never enters argv, so it never appears in ps.
  • It never hits disk in plaintext — only as ciphertext in the repo.
  • The agent reads only result.json, which contains no value.
