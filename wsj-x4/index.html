01

The mismatch

The site is not the edition.

A newspaper homepage is a constantly changing surface. The object I wanted was different: one day’s finite set of stories, in editorial order, with enough structure to browse offline. An EPUB is excellent at that job—but only if the pipeline preserves the edition’s shape instead of dumping a pile of pages into a zip file.

The design question: How do you turn a subscriber’s authenticated, dynamic reading experience into a calm, bounded personal artifact without storing the subscriber’s credentials?

02

The pipeline

One command. Six explicit stages.

The pipeline discovers the current edition, deduplicates story URLs, attaches to the already logged-in Chrome session, extracts readable article content, builds a standards-shaped EPUB, and delivers it over WebDAV. Each stage leaves evidence the next stage can inspect.

DiscoverFind the day’s edition and preserve its ordering.
AuthenticateReuse the human’s live browser session; never serialize a password or cookie into the repository.
ExtractKeep headline, byline, body, and useful image relationships.
CleanRemove navigation and page furniture without flattening the article.
PackageEmit EPUB 3 navigation plus the compatibility NCX older readers still expect.
DeliverUpload to the reader and remember the edition in a local seen cache.
03

The boundary

The login stays with the human.

The code does not bypass a paywall and does not contain a credential. It operates in the user’s real, authenticated browser context for personal reading. That constraint makes the automation less convenient—and materially more trustworthy.

Repository contains

Discovery, extraction, packaging, delivery logic, and reproducible dependencies.

Repository does not contain

Passwords, exported cookies, subscription content, or a public redistribution mechanism.

This remains a personal-use workflow. A technically possible extraction is not blanket permission to redistribute subscription content.

04

The artifact

EPUB is a tiny website with stricter manners.

The book needs deterministic filenames, a manifest, a spine, navigation, media types, and valid XHTML. The most useful design work is restraint: typography that reflows, images that fit, sections that remain navigable, and no web chrome competing with a four-inch screen.

05

Failure modes

A successful download can still be a bad newspaper.

Duplicate URLs create repeated stories. Lazy-loaded images disappear. A browser session expires. A malformed story can poison packaging. The seen cache can mistake a partial run for completion. The pipeline therefore needs stage-level checks and a final artifact inspection—not just a zero exit code.

  • Discovery count and ordering are visible.
  • Authentication failure stops loudly.
  • Individual extraction failures are named.
  • The EPUB is validated before upload.
  • The edition is marked seen only after delivery succeeds.
06

The lesson

Automation is interface design.

The CLI is the interface, the browser session is a trust boundary, the EPUB is the product, and the reader is the environment. Treating those as one end-to-end experience led to a better result than treating the project as “scraping some pages.”

What I would teach: start with the artifact you want to hold, then design every stage backward from what that artifact must preserve.

A finite edition for a tiny screen.

Discover honestly. Preserve structure. Deliver a real book.
